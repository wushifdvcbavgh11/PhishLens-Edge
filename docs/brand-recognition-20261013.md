# CPU 品牌识别修复 — 2026-10-13

## 范围

保留 FastAPI、MV3 和现有 AWL / OCR-aided Siamese 权重。未引入云服务、NPU 或新 OCR 依赖。
原始代码备份位于 `.maintenance/baselines/brand-fix-20261013/`。

## 识别与判定

- 全量重算上游参考图与本地品牌 App / 网页图标的特征。对每张图显式记录品牌、官方域名、尺寸、内容哈希和特征行顺序，并校验模型哈希。图片换内容但数量未变也必须重建。
- 透明图像先合成到白底，再使用既有 Siamese 等比例补边预处理。
- 首轮实际截图回放中，正确品牌虽排第一，但低分辨率图标与高清参考图产生分数偏差。对相似度至少 0.75 的短名单，再对三个不同品牌公平执行等比例分辨率对齐（短边最高 64 px），保留原分数与对齐分数；最终确认门槛仍为 0.90 / 0.04，不降低阈值。参考图的对齐特征采用 128 项有界缓存。
- 扩展只发送可见图片位置、视口尺寸以及凭据容器的静态标题/标签；服务端从真实截图裁剪，图片 URL、alt 和标题不能单独确认品牌。
- 去重后最多分析 10 个区域。首先把参考图结果合并到品牌，再比较不同品牌之间的分数差。
- 初始门槛为相似度 0.90、不同品牌差距 0.04、宽高比例差不超过 2.5 倍；不是识别概率，也未宣称经过独立大样本校准。
- 整页顶部块只能提供诊断候选。可识别的第三方支付/登录控件不确认页面身份；多品牌冲突保持不确定。
- 识别不再调用会依据域名清空品牌的旧混合函数。域名采用精确主机或以点分隔的子域匹配。
- `block` 还要求：密码框所在的局部容器包含已匹配 Logo，且静态文字提及相同品牌。缺上下文、旧扩展、截图客户端均不能绕过关联要求。

## 诊断与扩展

返回 `visual_evidence`：检测框及检测分数、裁剪来源、前三个不同品牌候选、拒绝原因、阈值和参考库版本。日志不存截图或输入值。

后台标签显示切回提示，并在恢复可见后防抖重试一次。每轮清理旧错误，过期截图回调无法覆盖当前诊断。没有 Logo、品牌歧义、多品牌及无法关联表单分别显示具体原因。

滚动隐藏 Logo 时提示返回可见位置重试。本次没有跨页面/内容版本复用旧品牌或旧 allow 结果，以免将过期识别带到新的登录表单。

## 验证与限制

自动回归覆盖多框、同品牌多图、不同品牌歧义、第三方控件、表单不关联、DPI 坐标、参考图哈希变化、后台重试、迟到回调及旧错误清理。

真实模型回放报告位于 `.maintenance/brand-fix-20261013/real-model-replay.json`（运行验收后生成）。包含当前浏览器演示页、官方域名上下文、无关密码框、第三方控件、2 倍 DPI、Logo 被遮挡、纯截图模式和无品牌登录页。派生图片与原图有共同来源，不能用于宣称独立准确率。

现有历史数据集曾发现重复，不将旧准确率沿用到本策略。仍需独立收集并按网站/模板划分真实验证集，测量品牌错误率、误拦率、漏检、不确定比例与延迟。参考库可能含近似或共享品牌标识；多品牌页面、宽页面布局、无文字 Logo 和跨容器登录会倾向不确定。

原有普通表单提交保护保留；没有宣称可以拦住 AJAX、原生 `form.submit()`、跨域 iframe 或任意脚本网络请求。
